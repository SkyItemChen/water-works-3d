# Waterworks 3D

> **每一块都在决定水的命运**
> Strategy / Puzzle / Relaxing · 纯单机 · 100% 确定性水模拟 · 无网络请求

一个从零实现的 3D 体素轻策略解谜游戏。你在竖井中投放体素块，引导清水与污水进入正确的排水口；可以预判、可以回放、可以用一个短码把通关解法分享出去。

## 快速开始

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 类型检查 + 生产构建
npm run test     # Vitest：104 个测试
```

要求 Node 18+，浏览器需支持 WebGL2（Chrome / Edge / Firefox / Safari 15+）。

未安装依赖时如果 npm 缓存目录被占用报 `EPERM`，可以指定本地缓存：

```bash
npm install --cache ./.npm-cache
```

## 新手教程

主菜单 → **新手教程**（未看过时带「新」角标）。5 步，全部跑在正式引擎上，没有任何教学专用分支：

| 步 | 目标 | 推进条件（引擎事件） |
| --- | --- | --- |
| 1 | 移动与落块，用土壤围池 | 锁定一块土壤 |
| 2 | 水囊落地破裂注水 | 锁定一块清水囊 |
| 3 | 清水进清水口 | 累计清水排出 ≥ 1 |
| 4 | 污水进污水口 | 累计污水排出 ≥ 1 |
| 5 | 管道转向 / 海绵吸水 | 锁定一块管道或海绵 |

- 教程状态机是**旁路观察者**：只读引擎快照，不写引擎、不进 `getStateHash()`、不进分享码、不影响回放。
- 推进只由离散事件驱动（块锁定 / 排水计数变化 / 混色），没有任何计时器参与。
- 「跳过教程」随时可用，同样记为已看过；首次进入不会强制弹教程。
- **中间步骤不播通关演出**：每一步其实都是一个完整关卡，通关即 win。但中间步只做水面排空（纯视觉），不拉远镜头、不弹结算、不生成分享码；切到下一步时相机同步 `refitForNewScene()`，把拉远位移和手动缩放一起清掉，所以 5 步的棋盘尺寸完全一致。只有第 5 步（教程完成）走正常通关表现，且同样不写星级/最佳分。

## 玩法

竖井是 **10 列 × 16 行** 的网格，顶部是溢出线，底部可放排水口。体素块从顶部下落，可以是地形，也可以是装水的容器。

| 块 | 尺寸 | 行为 |
| --- | --- | --- |
| 土壤 `soil2` / `soilL` | 2×2 / L | 永久地形，挡水、围池 |
| 水囊 `pocket` | 2×2 | 落地破裂，按 4 单位总量守恒注入清水，多余水量向上再分配 |
| 污水囊 `pocketDirty` | 2×2 | 同上，但注入污水 |
| 海绵 `sponge` | 1×1 | 最多吸 2 单位；满了失效；被压力挤压会吐水 |
| 管道 `pipe` | 1×1 | 带方向，水进入后强制转向，可旋转 |
| 沙块 `sand` | 2×1 | 被水压冲塌，变成土壤（压力足够大则消失） |
| 单向阀 `valve` | 1×1 | 只允许沿箭头方向通过 |
| 过滤器 `filter` | 1×1 | 污水通过变清水；累计过滤 3 单位后堵塞 |
| 冰块 `ice` | 1×1 | 水滑过不驻留 |
| 排水口 | 1×1 | 清水口（蓝）/ 污水口（绿） |

### 回放

分享码记录**完整操作流**（每一次左右移动、旋转、软降、硬降、保留，连同发生的 tick），回放时把同一串操作重新喂进同一个引擎，所以方块在屏幕上是**一格一格走、一行一行落**，而不是直接出现在落点。空格硬降在规则里是单 tick 完成的，渲染层会额外播放 0.18s 的下落动画把它表达出来。

### 水规则

- 每格容量 1；流动顺序固定为 **先下 → 再左 → 再右**；每个 tick 双缓冲结算。
- 清水为蓝色，污水为绿褐色；一旦混合，整格变为污水（交汇处会显示青色过渡层）。
- 水囊注入总量守恒；在场、已排、溢出、海绵吸存四者相加恒等于总下落量。
- 满格继续进水会累积**压力**：沙块先塌、土壤裂缝漏水、管道爆裂。UI 上有压力表、裂纹和危险列闪烁。

### 计分

| 事件 | 分数 |
| --- | --- |
| 清水进清水口 | +10 / 单位 |
| 污水进污水口 | +4 / 单位 |
| 清水进污水口 | −2 / 单位 |
| 通关剩余块 | +15 / 块 |

**失败条件**（都会明确显示原因，不会黑屏）：

1. 水位漫过顶部溢出线 → “第 4 列溢出”
2. 污水进清水口累计 3 单位 → “污水进清水口第 3 次”
3. 排水口被永久堵死 → “排水口被沙堵死”
4. 新块无空间生成
5. 块数用尽仍未达成目标

## 模式

1. **新手教程**：5 步，见上文。不强制、可跳过，与正式关卡共用同一引擎。
2. **合同模式**：30 个可玩关卡（数据结构支持 60 关），每 5 关引入一个新机制，末尾是组合考核与总验收。三星条件：完成目标 / 不溢出 / 剩余块数达标。
3. **每日挑战**：日期种子 + 固定块序，本地排行榜记录最高分与最少块数，含最近 7 天打卡。
4. **无尽模式**：水位随时间上涨，追高分。
5. **回放 / 分享码**：通关后自动生成短码（约 60–70 字符），其他人输入即可用相同种子回放整局。
6. **关卡编辑器（P2 预留）**：结构化关卡数据 + JSON 导入导出 + 只读棋盘预览。

所有进度存在 `localStorage`：关卡星级与最佳分、每日排行榜、分享码历史、无尽最高分、教程已看标记、设置。

## 确定性设计

这是整个项目的技术核心。

1. **纯函数模拟**：`simulate(grid, water, tick, config)` 不读写任何外部状态，不调用 `Math.random()` 或 `Date.now()`。
2. **固定顺序遍历**：自底向上、自左向右，每个 tick 先收集再统一写入（双缓冲），避免遍历顺序影响结果。
3. **整数/受控浮点**：水量使用 `Float64Array`，所有转移都来自同一组加减法，配合 `EPS` 阈值保证跨平台一致。
4. **种子化块序**：`mulberry32` + 7-bag。同种子必得同序列。
5. **回放按块压缩**：水场只取决于 tick 数与材料，因此分享码只需记录每块的 `tick / 列 / 旋转 / 是否保留 / 投放方式`，不需要记录每次按键。
6. **状态哈希**：回放结束时比对 `getStateHash()`，任何偏差都会被拒绝。
7. **教程是旁路观察者**：教程状态机只读引擎快照，不写引擎、不进哈希、不进分享码，因此「挂教程」与「不挂教程」的同种子同操作运行哈希逐位一致（有专门的回归测试）。
8. **回放复用引擎的终局判定**：回放不再靠「记录用完了」来停机，而是逐 tick 推进到引擎自己判出 `won`/`lost`。终局**判定**归引擎，终局**副作用**（结算、录分、分享码）归调用方——回放持有的是自己的引擎实例，从不调用 `onWin`，因此副作用天然为零。这两件事必须分开，不能用同一处短路控制。
9. **回放逐 tick 复现下落**：分享码记录的是**锁定** tick，回放不会在那一 tick 把方块瞬移到终态，而是提前把方块转向记录列/旋转，之后每个 tick 经引擎自己的软降路径下降一格，到记录 tick 才用 `A` 锁定。落地格永远由引擎算（`ghostY()` 每 tick 重读，沙块塌陷会改变落点），不是插值出来的。进度条长度直接用录制时写下的 `tt`（= 引擎停机的那一 tick），因此播放结束即 100%，没有空转尾巴。

测试覆盖：水量守恒、碰撞与堆叠、排水计分、同种子同结果、回放一致、篡改检测、回放自然终局、回放逐帧下落、进度条对齐、教程不扰动确定性。

## 三个“哇时刻”

| 时刻 | 实现 |
| --- | --- |
| **清水污水交汇变色** | 每格独立记录 clean/dirty，渲染时按比例插值到青绿色并加发光脉冲（`VoxelRenderer.pickWaterColor`） |
| **压力爆发碎裂** | 沙块/管道超压时产生体素碎屑 + 冲击波光环 + 相机震动 + 低频爆裂音（`Effects` + `WowMoments`） |
| **通关排空拉远** | 胜利后水量在 2.8s 内视觉排空，相机用 `pullBack()` 缓慢拉远并抬高，露出空池（`CameraController.pullBack`） |

All three are pure presentation: they never feed back into the simulation.

## 已知边界

- 关卡编辑器为 P2 只读预览（数据结构与 JSON 导入导出已就绪）。
